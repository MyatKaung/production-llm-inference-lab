Turn a chat message into model input

Goal: see why the model receives token IDs and chat-control tokens, not your raw sentence.

Run these notebook cells

In practical-baseline.ipynb, run the model/tokenizer load cell, then the “Inspect the two representations” cell. It contains:

messages = [{'role': 'user', 'content': 'Explain caching in one sentence.'}]
rendered = tokenizer.apply_chat_template(messages, add_generation_prompt=True, tokenize=False)
encoded = tokenizer.apply_chat_template(messages, add_generation_prompt=True, tokenize=True, return_dict=True, return_tensors='pt')

Worked example

Your visible message is only Explain caching in one sentence.. The chat template adds model-specific role markers and an assistant-generation marker. Then tokenization converts that rendered text into numeric IDs:

visible text → chat-formatted text → input_ids + attention_mask
"Explain caching…" → "<system/user markers…>" → [151644, …]

input_ids are the model’s vocabulary indexes. attention_mask marks real tokens with 1 and padding tokens with 0. With one unpadded prompt it is normally all 1s.

Practical experiment

# Change only this line, then rerun the inspection cell:
messages = [{'role': 'user', 'content': 'Explain KV cache in one sentence.'}]

Compare the two runs:

  1. Did the rendered template keep the same role/generation structure?
  2. Did input_ids change?
  3. Did the token count equal the number of visible characters? Why not?
Expected reasoning

Template structure should stay similar, token IDs change with text, and tokens are learned subword units—not characters or necessarily whole words.
