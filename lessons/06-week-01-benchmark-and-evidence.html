Goal: learn why one fast-looking answer is not a benchmark. You will run the fixed prompt set repeatedly, then inspect the JSON evidence the notebook writes.

Worked example

For each prompt class, the notebook first warms the model up, then saves five rows with input tokens, output tokens, total latency, and effective output-token rate. A warm-up is excluded because first-use work can distort the steady-state comparison.

python -m json.tool week-01-baseline-server/baseline.json | head -80
  1. Confirm there are five measured rows each for short, medium, and long.
  2. Find the long prompt’s input-token count.
  3. Compare its total latency with the short prompt’s latency.
  4. State one careful conclusion and one thing this file does not prove.

Careful conclusion: longer input was associated with higher end-to-end latency in this fixed setup. Not proven: pure prefill time, queue time, or a universal performance claim across hardware.

Why save JSON instead of only notebook output?

Notebook screens are hard to compare or reproduce. Machine-readable JSON can later become plots, tables, and before/after optimization evidence.
